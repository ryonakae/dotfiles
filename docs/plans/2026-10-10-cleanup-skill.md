# Cleanup Skill Implementation Plan

## Requirements

リポジトリに蓄積した不要な実装・テスト・説明を、現在の仕様と照合して整理する共通スキルを作る。次の二つを独立した探索観点として扱う。

- 削除・変更の痕跡：「削除済み」「もう使わない」「以前は」「変更していない」など、現在の理解に不要な説明、過去との比較、削除の事実だけを確認するテスト。内容が事実でも整理対象にする。不要な段落は説明に書き換えず削除する。
- 役目を終えたもの：未使用の実装・補助物、古い手順、現行仕様と食い違うテスト、不要な重複。未使用らしいことと削除可能であることを区別する。

現在必要な動作、公開契約、移行・互換性、データ保護、設計理由、出自・ライセンス、履歴そのものを目的とする記録は保持する。固定資料を保持する判断を、その周囲のREADMEや現行手順へ一律に広げない。好みによる再設計や削除件数の達成を目的にしない。

対象は実装・テスト・文書・エージェント指示・自作スキル・付属README・設定内の注記。検索で見つけた箇所だけを確認せず、対象ファイルを列挙して一つずつ読む。数値配列・バイナリ・外部管理物などの扱いは役割に応じて分け、除外と未確認を明示する。

compactやセッション中断に備え、対象リポジトリのルートに一時記録 `CLEANUP.md` を置く。作業中は逐次更新し、未完了なら保持する。完了報告を出したら削除し、コミットしない。削除理由や掃除済みの注記を製品コード・現行ドキュメントへ戻さない。

## Implementation Decisions

- 正本は `config/.agents/skills/cleanup/SKILL.md`。他プロジェクトでも使える、ツール固有のオーケストレーションに依存しないスキルにする。
- descriptionは明示的な掃除・一掃・不要物整理の依頼を入口とし、通常の開発中に勝手にリポジトリ全体を変更しない。調査だけの依頼なら洗い出しに留め、整理依頼なら根拠確認・修正・検証まで行う。
- `CLEANUP.md` の短い記録形式をスキル内に示す。目的・対象/除外、ファイル別の確認状況、指摘と根拠/対応、検証結果、次の作業を記録する。確認済みファイルの内容を識別できるhash等を残し、再開時に変更を検出する。大きなファイルは取得範囲を記録し、切り詰めや抜粋だけで読了にしない。
- 初回に既存差分を把握する。既存の `CLEANUP.md` は同じ作業と確認できる場合だけ継続利用し、無関係なファイル・symlink・他者の変更を上書きしない。作業自身が管理する記録だけを完了時に削除する。記録を隠すためのignore設定変更はしない。
- ファイル確認・修正の一区切りごとに記録を更新し、再開時には最初に読む。未読、要修正、判断保留、検証待ちを区別し、見つけた指摘の対応だけで全体完了にしない。調査後に整理を継続する場合も同じ記録を使う。
- 未知キー拒否など現行契約を検証するテストは維持し、不要な旧設定名・重複ケースと区別する。削除完了の確認は作業中に行い、恒久テストを追加しない。
- 分担する場合も対象重複を避け、親が読取範囲と指摘の根拠を確認して記録を統合する。委譲自体を必須とせず、調査漏れや未検証を隠さない。
- 現行仕様が不明、動作変更やデータ保全に影響する候補は根拠を調べ、解決できなければ確認する。cleanupという名目で仕様を確定しない。
- 既存の共通・Claude向けmise globで配布可能。名前の列挙、Nix変更、新しい配置処理は追加しない。HOMEへの配布、commit/pushは別途承認された範囲だけで行う。
