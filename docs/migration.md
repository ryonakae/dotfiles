# 既存環境を移行・復旧する

[README](../README.md) / 既存環境の移行

古い Home Manager 管理から mise の直接リンクへ切り替える Mac 用。新規 Mac は[初回セットアップ](setup.md)、現行構成の更新は[日常操作](usage.md)を使う。

この移行は通常の setup を繰り返しても完了しない。現在のリンク・稼働サービス・旧世代を確認し、対象に合わせて進める。

## 切替前に準備する

1. 宣言・差分・関連テストを確認し、[候補をビルド](usage.md#ビルドと適用を分ける)する。
2. 旧 Nix 世代、変更するリンクの宛先、既存アプリの差分を記録する。秘密や環境変数を全量出力しない。
3. 旧環境が使える間に、不足する Homebrew パッケージと mise runtime を対象限定で準備する。全体 upgrade は行わない。
4. 配置に使う `mise.toml` の内容を確認し、そのファイルだけを trust する。
5. **Nix が旧リンクの所有を解除する前に**、実 HOME に対する mise の dry-run を時間制限付きで実行する。

適用済みの Nix 版 mise がある場合の dry-run は[配置再開のコマンド](troubleshooting.md#設定配置だけ再開する)を使える。この時点では apply を実行しない。別の mise 版を使う場合は、その版の標準構文を確認する。

既知の旧 Home Manager リンクによる衝突以外の問題や、未知の実体・時間超過があれば切替を止める。dry-run が通っても、その後の成功が保証されるわけではない。

## 所有リンクを引き渡す

1. アプリを新規起動しない切替時間を確保する。稼働中の Hermes を[管理関数で停止](apps.md#hermes-を停止更新する)する。
2. 引き渡すリンクと、失敗時に戻す旧 Nix 世代・対象データの保全を確認する。
3. 確認済み成果物を switch し、Home Manager の所有を解除する。先に同じ宛先へ mise を apply しない。
4. 終了コードと解除済み範囲を確認する。残った旧リンクは由来を調べ、未知のものは残す。
5. mise で直接リンクを配置する。新たなファイルが作られていた場合も、force で上書きしない。
6. 旧 Herdr hook の解除後、必要なら[標準 integration](apps.md#claude-code)を入れる。既存 settings の差分は保持する。
7. 新しい shell の本体・runtime・リンク・fish plugin・Herdr hook を確認し、必要なサービスだけ再開する。

途中で失敗したら止める。profile / Home Manager / mise / Homebrew / Herdr の変更済み範囲を確認してから、続行か復旧かを決める。旧世代や退避物の削除・GCは移行と同時に行わない。

## Homebrew を引き継ぐ場合

nix-homebrew の `autoMigrate` は、Homebrew 本体の追跡ファイル・`.git`・残存 vendor を Nix 管理へ置き換える。既存の Cellar / Caskroom・ユーザー追加 tap は保持する設計だが、本体へのローカル修正は引き継がれない。

適用前に本体の変更を保全する。ビルドだけでは移行しない。Nix 世代を戻すだけで、移行前の Homebrew 管理方式へ戻るとは限らない。

## 以前の状態へ戻す場合

Nix の標準 `--list-generations` / `--switch-generation` で旧世代への切替を検討する。ただし、以下は別に復旧する。

| 対象 | 確認すること |
|---|---|
| mise と Home Manager のリンク | 旧世代が同じ宛先を所有するなら、対象を標準 unapply で解除してから引き渡す |
| Git 正本の本文 | 後続の変更を失わないよう、対象の差分を確認して戻す |
| Homebrew アプリ・mise runtime | Nix 世代だけでは元に戻らない |
| macOS preferences | 変更前の値・型・未設定状態に戻す。元が未設定なら対象キーの削除が必要 |
| DB・Docker volume・認証 | 個別の整合したバックアップから復元する |

再起動やログアウトが必要な操作は、作業を保存してから行う。未知のリンクの一括退避、自動 rollback、バックアップへの上書きは行わない。
