# dig log: macOS 設定の Nix 管理拡張

## 目的・前提・制約
- 現在の dotfiles の macOS 設定管理を拡張し、新しい Mac でも操作環境を再現する。
- 既存の移行方針は現在の使い勝手の再現を基準にする（`docs/dig/2026-10-03-nix-migration.md`）。参考記事の好みの値をそのまま採用しない。
- 正本は `config/nix/darwin/preferences.nix`。専用オプションを優先し、未対応項目だけ個別に検討する。preferences 全量取得・全 plist コピーはしない。
- 現在の環境は Safehouse 内。設定の実適用・Dock 再起動は別途承認が必要。宣言削除や世代 rollback だけでは preferences を復旧できないため、適用前に対象キーの旧値・型・未設定状態を記録する。
- 既存の他者差分は保持する。実装計画・実装にはそれぞれ承認を得る。

## 決定事項
- 最終方針は「標準機能で現在の動作を表現できるものだけ」。独自 activation、スクリプト、辞書更新処理を追加しない。
  - 出典: 計画提示後の「無理に複雑にしすぎない。nix標準機能で管理できるものだけにする」と、縮小した計画への「ok」。
  - 下記の当初の標準ショートカット・電源管理の希望は、この制約により今回の対象外へ変更する。具体的な実装・検証は `docs/plans/2026-10-05-macos-preferences.md`（完了後は archived 配下）を参照。
- 入力補正、スクリーンショット、Dock、Finder、メニューバー、操作・外観、キー割り当て、電源を Nix 管理の対象とする。
  - 出典: ユーザーの今回の依頼。
- キー割り当ての範囲に macOS 標準ショートカットを含め、アプリ別メニューショートカットは含めない（Q1 回答）。
  - 出典: 「アプリ別ショートカットはほぼ使っていないので管理不要、macOS 標準ショートカットは管理したい」。
  - 現在の割り当てと無効化状態を調査し、内部 ID の意味と反映方法を確認する。辞書の部分的な書き込みで他の割り当てを失わない管理方式を検討する。
- 電源設定は現在の値と、バッテリー時・電源接続時の違いを維持して管理する（Q2: A）。Nix 化と設定値の見直しを混ぜない。
  - ディスプレイのスリープ: バッテリー時2分、電源接続時10分。
  - 本体のアイドルスリープ: バッテリー時1分、電源接続時0（無効）。
  - その他の電源設定も現在値を基準とし、電源種別ごとの差を失わない。
  - 出典: 現在値を提示した Q2 に対するユーザーの「a」。
- 過去の dotfiles に記載された Dock 高速化も管理する。
  - 出典: ユーザーの今回の依頼。
  - 調査: `0463849`（2018-06-26）で README に `autohide-time-modifier = 0.15`、`autohide-delay = 0` の手動設定手順を追加。`ab60631`（2026-10-03）の README 簡素化で削除された。
  - `3af1942` の Nix preferences 導入ではこの2項目は移行されなかった。移行計画の当時の30キー確認にも含まれていない。
  - 2026-10-05 の対象キー個別読取では、実機の `autohide-delay` は float 0、`autohide-time-modifier` は float 0.1500000059604645。後者は旧記述の 0.15 に対応する浮動小数点表現。実機設定は残っているが再構築用の宣言が欠けている。

## 対象外
- 最終計画では macOS 標準ショートカット、電源設定、デバイス別キー割り当ても対象外。現在の設定は変更しない。
- macOS の「アプリのショートカット」によるアプリ別メニューショートカット（NSUserKeyEquivalents）。
- Apple ID、指紋登録、TCC、秘密・Keychain、認証データ。
- 今回列挙されていない sudo 認証、ネットワーク・ファイアウォール、フォント、サービス運用の変更。
- 実機適用・サービス再起動は未承認。実装・検証は承認済みで、Safehouse 内 build 失敗後に Herdr の通常ペインでの非適用 build も追加承認された。

## 未決・保留
- 各分野の対象キー・現在値・未設定時の実効値の確認。未設定を直ちに管理不要と判断せず、復元したい振る舞いを確認する。
- 電源・標準ショートカット・デバイス別リマップの追加調査は、最終方針で対象外となったため実装条件にしない。
- Q3 は A（計画作成）で承認済み。その後、標準機能のみへ範囲を縮小し、実装も承認された。
- デバイス別キー割り当てのマシン固有性、共通設定とホスト別設定の分離は実態調査後に判断する。
  - `hidutil property --get UserKeyMapping` は `(null)`。この結果だけではシステム設定のデバイス別修飾キー割り当てが存在しないとは判断しない。
- `com.apple.symbolichotkeys` の `AppleSymbolicHotKeys` をキー指定で読取済み。有効・無効の両方があり、`enabled` のみの項目もある。動作名と内部 ID の対応は未検証。
- Dock の並びは対象キーを抽出して取得済み。標準 persistent-apps／persistent-others でパス・順序・表示を宣言し、履歴・GUID 等は含めない。
