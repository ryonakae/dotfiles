# dig log: ユーザーだけで完了できる新規 Mac セットアップ

## 目的・前提・制約
- 新しい Mac では switch 完了までコーディングエージェントを起動できない。README とセットアップ手順はユーザーが単独で進められる構成にする。
  - 出典: ユーザーの依頼。
- Mac mini の初回 switch は /etc/bashrc と /etc/zshrc の未知内容で停止した。内容確認後、未使用の .before-nix-darwin 名へ手動退避して通過した。
- 続いて com.apple.universalaccess への書き込みで停止した。実行元 Terminal にフルディスクアクセスを付与すると先へ進んだ。switch 全体の完了は未確認。
- scripts/dotfiles.py の switch は Git snapshot に対して check と build を行い、対話確認後に適用する。別途 build は実装上の前提ではない。
- ユーザー向け手順の正本は .agents/skills/dotfiles-setup/references/setup.md。README に詳細を重複させない。
- 初回は macOS 標準の zsh と既存の OS コマンドだけで開始できる必要がある。fish、mise、Homebrew、エージェントを導入前から要求しない。

## 決定事項
- README と setup.md の分かりにくさを解消し、今回の停止への対処を記載する。
  - 出典: ユーザーの依頼。
- フルディスクアクセスで先へ進んだことは実機確認済みとして扱うが、すべての書き込みエラーの原因を同権限に断定しない。

- README は短い入口とし、setup.md は新規 Mac の時系列手順を先頭に置く。日常運用・既存 Mac 移行・機能別資料は後段に分離する。ユーザー承認済み。
- 初回の通常経路は switch 一回。別途 build は適用せず検証する場合に使う。
- 完了範囲はエージェントを起動できるところまで。エージェントの認証・秘密の登録方法は含めず、ユーザー側で準備する。起動 wrapper の必須前提だけ明記する。
- App Store を開いてサインインし、Xcode を先にインストール・起動してライセンス同意と初期設定を済ませる。購入時のパスワード要求頻度の調整は任意。これはエージェントの認証とは別の導入前提として扱う。
- 追加依頼: switch に bashrc / zshrc の内容・退避先表示と明示確認を追加し、承認後に退避・適用する。既存バックアップは上書きせず、管理済みリンクは触らない。不明なリンク・ディレクトリ・退避失敗では適用しない。CLI 入口と一時ファイルでの検証方法も承認済み。
- 追加依頼: Nix 版 fish をログインシェルにする手順を記載する。`environment.shells` で利用可能なシェルに登録し、設定配置後にユーザーが `chsh` を実行する。ユーザーが手動手順を選択したため、switch からの自動変更は行わない。
- 操作する側の呼称を「ユーザー」に統一するよう依頼され、リポジトリの該当表記を変更済み。

## 対象外
- 実機の設定変更・適用、秘密の操作、TCC 権限の自動付与、失敗時の自動再試行、commit / push は行わない。
- macOS 設定とアプリ導入の適用順序は変更しない。

## 後続の決定

- ユーザーの追加依頼により、上記の「通常経路は switch 一回」「switch 内で check と build を行う」は置き換えられた。build は検査・ビルド、switch は明示された成果物の適用、setup は両者と確認付き mise 配置を組み合わせる。初回・既存 Mac 共通で使い、chsh と runtime install は含めない。
- sudo は適用直前に認証し、適用中だけ標準キャッシュを更新する。パスワード保持や expect・sudoers の変更は行わない。
- 詳細は[後続計画](../plans/2026-10-12-setup-build-switch.md)を参照する。
