# dig log: Hermes の変更時だけ停止を要求する

## 目的・前提・制約
- 電源・スクリーンセーバーなど Hermes と無関係な変更を、Hermes を停止せずに適用できるようにする。
- scripts/dotfiles.py の switch は現在 hermesCheck を無条件に実行する。nix/home/hermes.nix も配置前後の停止チェックと plist の再配置を無条件に実行する。
- 起動定義は Hermes 本体・生成 wrapper の store パスを参照する。PATH に Home Manager のパッケージ環境も含まれるため、比較では間接的な変更も考慮する。
- サービスの自動停止・再起動、管理関数の迂回は追加しない。
- 他作業の変更がある config/.config/fish/functions/hermes-gateway.fish、scripts/tests/test_agent_runtime.py、docs/apps.md などは上書きしない。
- 複数の適用段階に関わる変更のため、設計確認・計画承認後に実装する。

## 決定事項
- Hermes の本体・wrapper・起動定義などが変わる場合だけ停止を要求する。
  - 出典: ユーザーの「これにして」。
- Hermes 関連の成果物が変わらない場合は、起動定義の再配置も省く。
  - 出典: 同上。
- 無関係な変更時の一律停止を撤廃する。停止チェック自体を全削除する方針ではない。
  - 出典: 会話中の合意。

## 対象外
- Hermes の自動停止・再開や状態保存。
- 今回の承認に基づかない実サービスの停止・実機適用。
- 既存のパスワード即時要求設定の変更を取り消すこと。

## 追加の決定事項
- 比較は生成された起動定義に集約し、本体・wrapper の store 参照もこの比較で検出する。独自の履歴や汎用的な差分管理は追加しない。
  - 出典: 「実装を複雑にしすぎないでください」「それで進めて」。
- Q1 は、初回配置・変更時は停止確認、配置衝突・読み取り失敗はエラーとして中断する方針で解決した。停止による自動修復は行わない。
- switch の適用境界と Home Manager の生成 activation をテストし、実サービスには触れない。
  - 出典: 計画承認「ok」。
