# t3-merge

ユーザーが PR の作成またはマージを頼んだときの手順。完了報告で自分から提案しない。リポジトリがマージの手順を独自に持つ場合（スキル、AGENTS.md の記述など）は、この手順ではなくそちらに従う。リポジトリの指示が一部の段階だけを置き換えたり足したりしている場合は、その段階だけ指示に従う。

プロジェクト設定が現在の場所での作業（`defaultThreadEnvMode` が `local`）でも、明示的に頼まれたらこの手順で行う。リモートや GitHub がなく PR を作れないリポジトリでは、その旨を伝える。

PR の作成・マージ・スレッドへの紐付け・watch に使うツールは、T3 Code が注入する指示に従う。

## 依頼ごとの範囲

| 依頼 | 行う段階 |
|---|---|
| commit だけ、commit と push だけ | この手順を使わない。`commit-push` スキルに任せ、ブランチを切らない |
| PR を作って | 1〜3 |
| PR を作ってマージして | 1〜7 |
| 既存の PR をマージして | 対象の PR を確かめ、未コミット変更も未 push の commit もなければ 4〜7 |

上から順に進め、失敗したらそこで止めて報告する。

## 1. ブランチを決める

`t3_worktree_status` と `git status --short` で、作業場所・ブランチ・未コミットの変更を確認する。

- 既定ブランチにいる: 変更に合う名前の作業ブランチを切る。名前はリポジトリの既存ブランチの命名に合わせる
- worktree にいる: 今のブランチのまま進める。T3 の自動名でも変えない

## 2. commit・push する

- 未コミットの変更がある: `commit-push` スキルの手順で行う
- 作業ツリーがきれいで未 push の commit だけがある: それを push する
- どちらもない: 次へ進む

push はローカルと同じ名前のリモートブランチへ行い、upstream を設定する。別名へ付け替えない。T3 は、スレッドのブランチと同じ名前の PR がマージされたときに worktree を片付ける。

## 3. PR を作る

基点は、worktree の作成元のブランチ、または手順1で作業ブランチを切った元のブランチにする。`main` に固定しない。

開いている PR は、head のリポジトリ・ブランチと基点がすべて一致するものだけ再利用する。別 fork の同名ブランチや基点の違う PR は使わない。なければ作る。

- タイトル: 基点ブランチの直近のマージ済み PR の形式と言語に合わせる。履歴がなければ `commit-push` のコミットメッセージ規則に合わせる
- 本文: リポジトリに PR テンプレートがあればそれを使う。なければ次の見出しにする。末尾には、その時点の attribution の指示に従った行を付ける

```markdown
## 変更
- 

## 確認
- 
```

PR はスレッドに紐付ける。

## 4. マージする

PR の mergeable とチェックの状態を確認する。

- コンフリクト、チェックの失敗、レビューの要求が一つでもある: マージせず、状態を報告して止める
- 上がなく、チェックが待ち・実行中: マージせず、PR を watch して手を返す
- マージできる: マージする

`--admin` や強制 push で通さない。

マージ方式は、基点ブランチの直近のマージ済み PR と同じにする（merge commit・squash・rebase）。履歴がなければ merge commit にする。その方式がリポジトリで無効な場合や、履歴から判別できない場合は、許可されている方式が一つならそれを使い、複数ならユーザーに確認する。

T3 Code は、マージされた PR の worktree を片付ける。マージ後に実行する処理（配信、デプロイ、タグ付けなど）があるリポジトリは、worktree が消えても成立する形（マージと同一コマンドへの連結、primary checkout からの実行など）を、そのリポジトリの手順で定める。そうした手順があれば、この段階でそれに従う。

primary checkout で作業していた場合は、マージ後に基点ブランチへ戻し、`git pull --ff-only` で更新する。

## 5. ブランチを消す

消す対象は、マージした PR の作業ブランチと、このスレッドの子タスクが作ったブランチに限る。既定ブランチ、PR の基点、`develop` などの常設ブランチ、どこかの worktree で使用中のブランチは消さない。

- リモート: GitHub のマージ時ブランチ自動削除が無効なら、マージした PR の作業ブランチを消す
- ローカル: primary checkout で `git fetch --prune` を実行し、追跡先が消えていて PR の基点に取り込み済みのブランチを `git branch -d` で消す。取り込み済みというだけでは消さない

今のスレッドのブランチは worktree で使用中なので残る。T3 が worktree を片付けた後、次にこの手順を使ったときに消える。

## 6. スレッドの付随物を片付ける

`use-t3-code` スキルの [references/thread-lifecycle.md](../use-t3-code/references/thread-lifecycle.md#付随物を片付ける)「付随物を片付ける」に従い、このスレッドと子タスクが作ったものを片付ける。

## 7. 報告する

PR の URL、merge commit、消したもの、残したものとその理由を書く。GitHub のマージ時ブランチ自動削除が無効のままなら、有効化の提案を1行添える。設定は承認されてから変える。

## 含めないこと

スレッドの settle と worktree の削除は行わない。PR のマージ後に T3 Code が行う。
