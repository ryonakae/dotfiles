# 計画書レビュアー用プロンプト

ユーザーがレビューを求めた場合、または誤判断の影響が大きく自己レビューだけでは確信が持てない場合に使う。

```text
計画を read-only でレビューする。目的は、合意した変更を過不足なく実装できるかの確認。

計画: [PLAN_FILE_PATH]
元の要件・合意: [SPEC_OR_CONTEXT_PATH]

確認すること:
- 合意済みの振る舞い、制約、対象外を保持し、未確定の公開仕様を勝手に決めていないか。
- 変更対象と方針が既存コードに合い、各要件を実現するタスクが読み取れるか。
- 検証が主要な回帰リスクを押さえ、期待結果から完了を判断できるか。コマンドや参照先は実在するか。
- 検証や実装の手数を増やすだけの重複、要件外の再設計、作業完了だけを証明するテストがないか。
- 未検証を完了扱いせず、要件変更は確認し、必要なゲートの通過後にアーカイブする指示があるか。

短いこと、任意の節・要件 ID・対応表・N/A 一覧がないことを欠陥としない。
自動テストを増やす提案には、守るべき継続的な振る舞い・契約と、既存の検証で不足する理由を示す。
削除や置換だけの確認には差分レビューや一度の検索を認める。不在そのものが安全要件・公開契約ならテスト対象にする。

要件の欠落、誤実装、実装の停止、進捗の誤認、不要な作業につながる具体的な問題だけを報告する。
実装の内部詳細や好みの方式を追加要求せず、指摘がなければ Approved として終える。

出力:
Status: Approved | Issues Found
Issues:
- [箇所]: [問題] / [違反する要件または具体的なリスク] / [最小限の修正案]
```
