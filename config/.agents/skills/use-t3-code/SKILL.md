# Use T3 Code

## 最初にサブエージェントへの委譲を判断する

原則として、現在起動中の親モデルで作業を完結させる。小〜中規模の実装・修正や局所的な確認は、ハンドオフ負荷（依頼文作成・子の初期読込・文脈欠損）が利益を上回るため直接処理する。スキルを読むことは必須だが、すべての依頼でサブエージェントを起動する必要はない。

次の発動条件に該当する場合にサブエージェントへ委譲する。開始時に直接処理すると決めても、作業が広がったら判断し直す。

- **独立レビュー**: `plan`・`implement` が求めるレビュー（レビュー要否の正本は各スキルに従う）、またはそれらを使わない通常作業での数行を超える差分の完了報告前
- **コンテクスト保護・並列化**: 読む対象を事前に特定できない横断探索、互いに依存しないまとまった並列作業
- **局所難所への上方委譲**: 親が最上位ティアでない場合に、依頼文へ切り出せる難所（原因調査、設計案の検証、局所的な難実装）。作業全体が難所なら子へ投げず、親モデルの切り替えをユーザーへ提案する
- **速度・費用・枠節約**: 範囲と手順を依頼文に書け、結果を機械的に確かめられる探索・確認の軽量ティアへの委譲
- **読者向けの文章**: 親が [models.md の文章スロット](references/models.md#文章スロット) と異なる系統の場合の、README・Web コピー・UI テキストなどの文言案作成・推敲

## 作業場所を判断する

依頼を受けたら、編集より先に作業場所を決める。大半の作業は現在の場所で進め、worktree を作るまでもない作業で worktree を提案しない。最初は読取調査でも、変更を進めることになった時点で判断し直す。

| 依頼 | 作業場所 |
|---|---|
| 質問への回答、読取調査、レビュー、計測 | 現在の場所。質問への好意的な反応を実装依頼と解釈しない |
| 誤字・リンク・設定値など、内容と影響が明確で局所的な修正 | 現在の場所 |
| 判断に迷う中間の作業（1ファイルで完結する不具合修正、依存1件の更新、小さな UI 調整など） | 現在の場所 |
| 同じ依頼の続き、レビュー指摘の修正 | その依頼の場所を継続する |
| dig・Plan に進む変更、複数の commit に分かれる規模の変更（機能追加、複数箇所にまたがる修正、整理、性能改善）、PR でのレビューや確認が要る変更 | [t3-worktree](../t3-worktree/SKILL.md) を読み、新しい worktree を提案する |

現在の場所に他の作業の未コミット変更がある場合と、他のスレッドが同じ checkout で作業中の場合は、規模にかかわらず t3-worktree を読む。

判断の材料が重なったときは、次の順で優先する。

1. ユーザーによる作業場所の指定（「今のブランチで」「新しい worktree で」など）
2. リポジトリ独自の手順（スキル、AGENTS.md の記述など）。あれば、この節と t3-worktree ではなくそちらに従う
3. T3 のプロジェクト設定（t3-worktree の手順で確認する）
4. 上の、他の作業と重なる場合の扱い
5. 表

worktree は、理由・基点・ブランチ名を示してユーザーの承認を得てから作る。ユーザーがその依頼で worktree を明示していれば、作成は承認済みとして扱う。

## サブエージェントのモデル・思考レベル

委譲すると決めたら、親と同一モデルに固定・制限せず、[references/delegation.md](references/delegation.md) の手順と [references/models.md](references/models.md) のモデル表から、ティア・用途・別系統（およびプロバイダ別の使用量枠分散）に合うモデルと開始 effort を選ぶ。選定の結果、親と同一プロバイダ・同一モデル・同一オプションになった場合だけ内蔵サブエージェントを使い、それ以外は `delegate_task` で明示指定する。

ユーザーの明示指定がある場合は、モデル表より指定を優先する。委譲時の作業場所、依頼内容、結果の確認方法、プロバイダ固有制約も [references/delegation.md](references/delegation.md) を確認する。

## T3 Code の指示との役割分担

T3 Code が注入する指示に、この環境での判断基準と運用を補う。
`delegate_task`・`task_status`・`device_*`・`t3_thread_organize`・worktree 隔離などのツールの使い方と、内蔵機能と `delegate_task` のどちらを使うかは T3 の指示に従い、ここで再定義しない。

## 回答の HTML 表示

回答を HTML で表示する場合は、`html_preview` で確認し、`html_render` で会話内に表示する。配色、書体、余白は `html_render` のスタイル指示に従う。
