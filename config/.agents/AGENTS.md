## 開発スタイル

- チャットでの応答は日本語。システムエラーやログの引用は原文のまま
- ドキュメント、コード内コメント、コミットメッセージは、既存方針を優先しつつ、公開リポジトリでは英語、非公開リポジトリでは日本語を基本とする
- 実装前に、仕様・設計・計画を記述するドキュメントや決定記録があれば読む。実装で判断が変わったり、意味を失ったコード・テスト・記述が出たりしたら、同じ変更で更新・削除し、矛盾や古い記述を残さない
- テストが整備されているプロジェクトでは `tdd` スキルで実装する。テストを書く前に、守るべき振る舞いを決める。落ちたときに何が壊れるか言えないテストは書かず、仕様が消えたテストは消す
- 作業の検証と、恒久的に保守する成果物を区別する。テストは依頼の達成証明ではなく、今後も守るべき振る舞いのために残す。追加・変更時には、作業の経緯を知らなくても、その必要性を現在の仕様から説明できるか確認する
- 推測で進めない。コードやドキュメントで確認できることは確認し、確認できない曖昧さだけ質問する
- 依頼や計画にない変更は始めず、止めて確認する。一箇所の修正が共通部品の再設計に広がる、API やデータモデルの変更が必要になる、同じ不具合に局所修正を繰り返す、差分を一つの因果で説明できない、が兆候
- 最初から完成候補を出す。下書き→批評→書き直しを通常の手順に組み込まず、合格した検証を念のためで繰り返さない
- 複雑な要件の整理や重要な設計判断が必要な実装は、`dig` スキルで要件を詰める。ユーザーの承認後、`plan` スキルで実装計画を保存する。再承認後、`implement` スキルで実装する

## コード設計

- 既存コードの設計・記法に従う
- KISS: 触れる範囲のコードは、現在の要件に対して最も単純な形にする。後方互換・データ移行・非推奨経路の維持は、依頼されたか、公開 API や既存データに利用者がいる場合だけ行う。信頼境界の入力検証、データ保全、認証・権限確認、監査記録、アクセシビリティは簡素化の対象にしない
- YAGNI: 書く前に、そもそも必要か、既存実装・標準機能・導入済み依存で足りるか、1行で済むかを順に確認し、すべて否なら必要最小限を書く。依頼されていない抽象化や将来の足場（実装が1つのインターフェース、製品が1つの factory、変わらない値の config、誰も設定しないオプション）を作らず、簡単な処理のために新しい依存を追加しない
- DRY: 同じ知識・判断を複数箇所に書かない。ただし偶然似ているだけのコードを無理に共通化しない
- バグ修正は症状ではなく根本原因を直す。共通処理を変更するときは呼び出し元への影響を確認し、各所に同じ回避策を追加しない
- 単一責任で関心を分離する。状態とロジック、API・型・データ形式などのコントラクトと実装詳細を混ぜない。SOLID の他の原則はレビューの語彙にとどめ、原則のためにインターフェースや間接層を増やさない
- コメントは Why だけ。処理内容の説明は書かない
- 静的に検査できる規約は、プロンプトではなく linter・formatter・型・テストに寄せる

## ツール・環境

### 実行環境

- 作業開始前に `APP_SANDBOX_CONTAINER_ID` と `HERDR_ENV` を一度確認（明示済みなら不要）。環境変数の一括出力は禁止
- `APP_SANDBOX_CONTAINER_ID=agent-safehouse` なら Safehouse 内。制限操作は試さず、`Operation not permitted` は回避せず報告する。ただし `HERDR_ENV=1` なら依頼範囲内の非破壊的操作は Herdr の別タブ・ペインで実行可。破壊的操作・機密情報へのアクセス・権限やセキュリティ設定の変更は要事前承認

### コマンド・検証ツール

- ユーザーに提示するシェルコマンドや環境変数設定は、指定がない限り `fish` の構文で記述する
- worktree の操作は `git worktree` を直接使わず、`wt`（Worktrunk）と `use-worktrunk` スキルで行う
- Python: CLI ツールは `uvx`、スクリプトは `uv run`、パッケージ追加は `uv add`
- iOS Simulator での UI 動作検証や `.ad` テストの作成・実行には `use-agent-device` スキルを読み、公式 `agent-device` スキルも併用する。配置・初期状態・実行方法は対象アプリの既存規約を優先する

### ドキュメント・Web検索

- ライブラリ/API のドキュメントは `find-docs` スキルで参照する
- Web検索・ページ取得は一次情報（公式ドキュメント、API リファレンス）を優先し、検索/取得ツールの失敗時・未提供時や `403` エラーの場合は `agent-browser` をフォールバックに使う
