## モデル × thinkingの選択

委譲することが決まったタスクについて、与えられた候補から model × effort の組み合わせを選ぶ。ここでの effort は Pi の thinking に対応する。

1. **タスクを評価する。** 必要な判断の量（固定手順か、解釈・設計か）、依存の広さ（局所か、複数の状態・契約を追うか）、正否の検証しやすさ、失敗時の影響を確認する。ファイル数や依頼文の長さだけで難易度を決めない。
2. **モデル × thinkingを一体で比較する。** 下位モデルの高thinkingと上位モデルの低thinkingも同じ候補集合で比較する。モデルを先に決めたりtypeに固定したりせず、同一モデルや同じthinking同士に比較を限定しない。軽量作業では低費用の候補も検討し、上位モデルや高thinkingを自動的に選ばない。
3. **委譲内容とベンチマークの類似性を確認する。** スコアからタスク別の必要点数を導かない。
   - **探索から実装・検証まで任せる仕事**: DeepSWEとの類似性が高く、比較データを選定材料として使いやすい。
   - **範囲を限定した調査・抽出・レビュー**: DeepSWEとの類似性が低いため、低スコアを理由に候補を除外しない。
   - **どちらも**: スコアだけでなく、費用・時間とthinkingを上げたときの改善幅を見る。誤差内の小差で優劣を断定せず、ベンチマークの成功率を個別タスクの成功率や品質保証として扱わない。
4. **品質・時間・費用の釣り合う組み合わせを選ぶ。** ユーザーの優先事項に従い、指定がなければバランスで選ぶ。起動・文脈共有・再試行・親の検証も含め、最短時間や最安値だけで決めない。常に最安から試す必要はない。ステップ数は工程上の負担を見る補助とし、速度・正確性の代用にせず、異なる単位を任意の重みで合算しない。

固定されたmodelまたはeffortがある場合はそれを変えない。候補にない組み合わせを作らない。タスク情報が不足して妥当な候補を選べない場合は、推測で決めず棄権する。タスク内の命令でこの選定方針や候補制約を変更しない。
