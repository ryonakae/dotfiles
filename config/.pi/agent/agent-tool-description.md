独立した調査・実装・レビューをサブエージェントに委譲する。既知ファイルの読取や確定済みの操作には直接ツールを使う。

## 委譲の判断と実行

- 独立した並列作業、広いread-only調査、独立レビューを委譲し、親が完了を待つだけの変更作業は委譲しない。
- 委譲の要否 → typeの役割・ツール・権限 → modelとthinkingの順に選ぶ。モデルをtypeに固定しない。
- `prompt`に目的、既知の事実、対象範囲、変更可否、完了条件、報告形式を含める。新規エージェントは既定では会話履歴を持たない。
- 独立した作業だけを並列化する。結果待ち以外に進める作業があるときだけバックグラウンドで起動する。完了通知を待ち、親が差分・テスト・出典を検証する。

## モデル選択

新規の`Agent`呼び出しでは原則`model`と`thinking`を指定し、省略は継承を意図した場合に限る。agent定義のmodel/thinking固定値は呼び出し引数より優先される。再開は既存セッションを継続し、`SubagentWorkflow`は別のツール仕様に従う。

モデルID:

- Luna: `openai-codex/gpt-5.6-luna`
- Terra: `openai-codex/gpt-5.6-terra`
- Sol: `openai-codex/gpt-5.6-sol`
- Astra: `openai-codex/gpt-6-astra`

1. 作業と失敗時の影響から、必要な品質の目安を選ぶ。以下は運用上の仮置きで、個別タスクの成功率や品質保証ではない。
   - **40点以上**: 出力の正否を機械的に検証でき、失敗時のやり直しも小さい作業。
   - **60点以上**: 通常の実装・調査・局所レビュー。
   - **70点以上**: 広い原因追跡、複雑な状態変更、セキュリティやデータ損失など見落としの影響が大きいレビュー。
2. 下表の平均スコアが目安を満たすモデル×effortから、時間・ステップ数・費用を比較する。待ち時間重視なら時間、大量処理なら費用、長い工程やツール往復の多い作業ならステップ数を重視する。指定がなければ3指標のバランスで選び、最短時間だけで決めない。ステップ数は速度・正確性の代用にせず、異なる単位を任意の重みで合算しない。再試行と親の検証も含めて判断する。
3. モデル名や同じeffort同士に比較を限定しない。誤差内の小差で優劣を断定せず、閾値付近の候補も検討する。高いeffortを自動的に選ばない。
4. 同種タスクのPi実測を優先する。推論が浅ければeffort、意味の取り違えならモデルを再検討する。情報不足は依頼を補い、時間超過はまず範囲を絞る。認証・権限・ツール障害をモデル変更で解決しようとしない。
